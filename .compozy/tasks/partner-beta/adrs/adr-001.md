# ADR-001: Inactive Business Restrictions via Client-Side UI Disablement

## Status

Accepted

## Date

2026-07-24

## Context

For the "Partner Beta" soft launch, we need to limit the actions available to businesses that are "inactive" (not currently paying partners). Specifically, inactive businesses should not be able to create new coupon campaigns or publish posts to the feed. However, they should still be able to view their past data. Because this is a beta launch, speed to market is critical.

## Decision

We will implement restrictions purely at the client-side UI level. The dashboard will show a prominent warning banner for inactive businesses, and we will disable all "Create" and "Edit" buttons on the Coupon and Posts management pages. We will not add strict backend API checks for the `isActive` state on mutating endpoints for this phase.

## Alternatives Considered

### Alternative 1: UI-Level Disablement + API Security
- **Description**: Add 403 Forbidden checks to the backend API along with the UI disablement.
- **Pros**: Safest and most robust; prevents API abuse.
- **Cons**: Slower to implement, requiring changes across multiple API routes.
- **Why rejected**: Slower time-to-market for a beta launch.

### Alternative 2: Distinct "Inactive Dashboard" Layout
- **Description**: Redirect inactive businesses to a completely separate "Locked" dashboard layout.
- **Pros**: Very clear UX, no chance of confusing UI states.
- **Cons**: Requires building and maintaining two separate dashboard layouts.
- **Why rejected**: Unnecessary overhead for the current phase.

## Consequences

### Positive
- Fast implementation and rapid deployment for the beta.
- Allows inactive users to still access their historical data seamlessly.

### Negative
- A technically savvy user could theoretically bypass the UI and hit the API directly to create coupons or posts.

### Risks
- Potential for minor API abuse if discovered.
- **Mitigation**: Monitor API logs for unusual activity from inactive businesses; plan to implement API-level checks in a fast follow-up or Phase 2.
